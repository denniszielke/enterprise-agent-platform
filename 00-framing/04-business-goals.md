# Business Goals

> Status: Accepted
> Canonical owner: Not supplied
> Required reviewers: Not supplied
> Gate: G0
> Last reviewed: 2026-09-01

The goals below restate outcome statements in the supplied material. The measure names in the third column are supplied as measures only; they are source input, not baselines, thresholds, targets or results.

| ID | Goal as supplied | Supplied measure names, as source input only |
|---|---|---|
| `GOAL-001` | Reduce the amount of foundational work each agent project team has to solve on its own, so that AI projects do not start from an empty cloud environment and receive the minimum viable foundation for identity, network integration, runtime hosting, model access, telemetry and cost attribution before they begin building solution-specific logic | Onboarding time for a new domain team; share of production agents built on golden paths; number of domains with an agent in production; deviation requests per quarter |
| `GOAL-002` | Increase the trust, observability, security and accountability with which agents, agent-enabled applications, MCP servers, models, tools and data products are created and operated, by making identity, policy, auditability and lifecycle status visible | Task success rate per scenario; groundedness and citation coverage; escalation to human rate; safety filter trigger rate and false-positive rate; share of agents with current evaluation suites; evidence coverage for governance |
| `GOAL-003` | Enable developer teams to build business solutions faster through streamlined governance, release management, and cost management as a platform investment | Lead time from approved idea to production agent; change failure rate for agent releases; time to restore after an agent incident; share of releases passing evaluation gates first time |
| `GOAL-004` | Make models, tools, APIs, MCP servers, data products, semantic models and agents discoverable and consumable as managed enterprise assets, each with ownership, classification, lifecycle state, approved consumer scope and telemetry expectations, so that reuse becomes the natural default | Components consumed outside their owning domain; count of registered but unowned agents; age of the oldest unreviewed access assignment |
| `GOAL-005` | Manage AI impact as an operating discipline by capturing operating signals from the beginning and attributing model and tool consumption to projects, teams, agents or workloads with enough fidelity to support FinOps, optimisation and governance discussions | Cost per completed task or conversation; trend of unit cost as volume grows; attribution accuracy as the share of spend mapped to a scenario; budget variance per domain; value measure per scenario |
| `GOAL-006` | Map the 24 committed capabilities to accountable platform owners, implementation artefacts and decision points so that scope is not only documented but operationally actionable, with exactly one accountable owner per capability | Capability maturity scores per capability area |

The supplied material states that every cost metric should be paired with a value metric, and that vanity metrics such as the number of pilots or the number of capabilities delivered answer none of the questions the measures exist to answer.

## Guardrails

- Do not convert an aspirational outcome into a forecast, a commitment or a demonstrated result.
- State populations, units, time windows, and exclusions before any numeric claim is made.
